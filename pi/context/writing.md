# Writing

Applies to code, comments, docs and READMEs:

- Be as brief as possible while staying descriptive.
    Go straight to the point.
- No filler, repetition or padded sentences.
- No AI smells, such as em dashes.

## Markdown

Mandatory for any text that supports Markdown, such as `.md` files, doc comments, PR descriptions, commit messages and issues.

Write one sentence per line.

## Code documentation and comments

Mandatory:

- Keep them as brief as possible.
- Never leak implementation details into API docs, public or private.
- Add an in-code comment if, and only if, the code is not descriptive enough on its own and cannot be refactored to make it clear.
